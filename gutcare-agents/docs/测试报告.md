**真实调用暴露并修掉的三个问题**（都不是 mock 能发现的）：

1. 模型把 `trend_obs_011` 写成 `trend_obs_11`，导致一条建议被误删 → 引用解析改为“去前导零”规范化并写回规范编号；
2. 长句里的“目前无法确定是 A 还是 B 等因素导致……”被当成因果断言删除 → 否定判断从 12 字符窗口改为**分句级**；
3. “8月31日无记录”被当成编造数字 31 → 数值落地检查先剔除日期写法。

## 5. 责任交界处的约定（避免“都以为对方测了”）

1. **患者确认**：智能体只输出候选值与 `confirmation_fields`；确认、落库、版本由后端完成。
2. **未确认数据**：智能体排除 `pending_confirmation/deleted/superseded`，但“是否允许提交待确认记录”由后端决定。
3. **风险提示**：智能体提供规则引擎与规则文件；线上同步执行与去重归后端。两边规则版本需一致（`rule_set_version`）。
4. **依据更新**：智能体提供快照哈希与记录版本；旧建议标记“依据已更新”的展示逻辑归后端。
5. **通知与闹钟**：智能体只产生结构化结果与状态，不直接发通知。

## 6. 未覆盖 / 未验证（明确声明）

1. 报告字段抽取准确性、食物识别准确性：无字段级/可见食材金标准，只能人工核对。
2. OCR 字符错误率：测试包参考转写为 `pending_manual_transcription`，无金标准。
3. 排便图像分类：流程与边界测试已通过；无真实标注图像，准确率未测。
4. 视觉输入可用性：需真实 API Key 冒烟确认（开发环境无外网）。
5. 消融实验数值：需 live/replay 运行，mock 下脚本显式 `skipped`。
6. 并发与性能：未做压测；当前设计面向单机演示与联调（4 线程池）。
7. 临床有效性：不参与评测，也不作任何声称。

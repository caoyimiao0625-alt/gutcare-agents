# 第三方模型、外部数据与开源组件使用说明

> 对应大赛提交材料第 6 项“开源组件、第三方模型、外部 API 或数据集使用说明”。
> 本文件由代码事实整理，不含夸大表述；所有“未验证”的地方都明确标注。

## 1. 模型服务

| 项目 | 内容 |
|---|---|
| 供应商 | DeepSeek（OpenAI 兼容 `/chat/completions` 接口） |
| 作用 | 多模态理解与文本生成：医疗报告字段抽取、可见文字转写、医嘱文书抽取、单餐识菜、趋势叙述、建议生成、助手回答 |
| 接入方式 | 服务端 HTTP 调用，密钥只放在运行环境变量 `GCA_API_KEY`，不进入代码、仓库与日志 |
| 可替换性 | 任何 OpenAI 兼容服务都可替换（改 `GCA_BASE_URL` / `GCA_TEXT_MODEL` / `GCA_VISION_MODEL`），业务代码不含供应商专有逻辑 |
| 版本记录 | 每次调用的响应都会记录 `model_id`、`prompt_version`、`agent_version`，并与结果一起落库，保证同一任务可定位到当时的模型与提示词版本 |
| 能力验证状态 | **已于 2026-10-17 验证**（硅基流动，OpenAI 兼容接口）：文本 `Qwen/Qwen3-30B-A3B-Instruct-2507`、视觉 `Qwen/Qwen3-VL-30B-A3B-Instruct`。报告截图抽取 13 项、食物图 3 项、5 例综合分析 5/5 成功。实测时延：视觉约 47—55 秒/张报告图，文本 1—15 秒。若换用不支持图像的型号，接口会返回 `unsupported_media_type`，系统降级到手动录入或 `report_text_extract` 文本路径，不会伪造结果 |
| 失败处理 | 超时/5xx/429 → 指数退避重试（`GCA_MAX_RETRIES`，默认 2 次）；仍失败则该 Agent 降级，记录与安全规则继续可用 |
| 成本口径 | 按服务返回的 `prompt_tokens` / `completion_tokens` 记录到 `usage_log` 表，可随时用 `GET /v1/meta` 查看累计用量；**本仓库不预算价格**，实际费用以后台账单为准 |

**没有使用的**：微调、自建推理、向量数据库服务、第三方 OCR 服务、联网检索。知识检索为本地实现。

## 2. 外部数据（GutCare 测试包 v4）

测试包由团队整理，位于工作区 `testdata_v4/`，**仅用于测试与演示，不包含真实患者身份信息**。

| 数据 | 规模 | 来源与许可 | 本仓库用途 |
|---|---|---|---|
| 中文消化系统报告截图 | 87 份 | 公开脱敏医疗报告集（MedRepBench 类），含遮挡 | 报告抽取测试输入 |
| 食物图片 | 90 张 | Nutrition5k（公开数据集） | 识菜测试输入 |
| 模拟随访医嘱 | 87 份 | **合成**（由报告类别套用中性模板生成，图上标注“仅用于系统测试”） | 医嘱字段抽取测试 |
| 公开心情观测 | 90 条（原始 TSV 1254 行 / 24 人） | openESM 0029（IBS 合并惊恐障碍样本） | 量表字段与边界测试 |
| 合成患者与记录 | 90 名患者 / 3240 条记录 | **合成** | 趋势、综合分析、隔离与状态测试 |
| 参考答答案 | 540 + 87 + 90 + 90 条 | 团队编写 | 评测比对 |

使用约束（已体现在代码里）：

1. `reference_answers/` **不进入提示词、不进入知识索引、不作为智能体可读目录**；
   评测脚本只在评测进程中读取（`eval/` 下）。
2. 公开心情数据不能代表所有 IBS 患者，同一参与者的重复测量不视为不同患者；
   合成患者（SYN*）与外部参与者（EXT-*）严格分开，`patient_id` 是隔离边界。
3. 模拟医嘱不是医生出具的内容，代码中对 `clinical_use_allowed=false` 与“仅测试”标记做保留校验。
4. 测试包没有真实粪便图像，因此排便图像识别流程虽已实现，**不报告 Bristol 分类准确率**；也没有 OCR 逐字金标准，因此不报告 OCR 字符错误率。

## 4. 开源组件

| 组件 | 许可证 | 用途 |
|---|---|---|
| Python 3.12 标准库 | PSF | HTTP 服务、SQLite、JSON、并发、日志、测试 |
| Pillow（环境自带，可选） | MIT-CMU | 仅用于上传图片的方向纠正、缩放与压缩；缺省时自动跳过，不影响主流程 |

**没有引入** Web 框架、ORM、Agent 框架、向量库、检索库。设计取舍见
`docs/系统设计_智能体章节.md`（理由：可复现部署、离线演示、评审可读）。

## 5. AI 工具使用声明

按大赛通知“人工智能工具使用及作品真实性”条款如实说明：

- 使用 AI 编程助手辅助**代码草稿、文档初稿、测试用例枚举与审查**；
- 系统架构、Agent 职责划分、数据契约、校验与安全边界、评测方案由参赛队员确定，
  并可逐项说明其代码位置与取舍理由；
- 未使用 AI 工具伪造运行结果、测试数据或代码历史；仓库提交历史为真实开发过程；
- 所有“效果数字”均来自 `eval/` 脚本的真实执行结果，未测项目在报告中明确标注为未测。

## 6. 隐私与合规

1. 智能体只处理请求中授权提供的数据，不主动访问其他患者记录；所有记录的 `patient_id`
   与请求不一致时直接拒绝（`patient_scope_violation`）。
2. 不长期保存患者原始图片：默认识图后只缓存结构化结果（缓存键为文件内容哈希，
   可用 `options.no_reuse` 关闭复用）。
3. 日志不打印报告原文、药品信息或图片内容；错误信息只保留错误码与必要上下文。
4. 本系统定位为健康信息管理与辅助建议，**不是医疗器械**，不提供诊断、处方、剂量调整或急救响应。
5. 真实患者数据启用前，需完成：专业审核规则与知识、数据授权与保留/删除策略、
   第三方模型传输范围评估。

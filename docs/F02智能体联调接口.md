# F02 智能体联调接口

更新：2026-10-21。本文描述**已在智能体仓库实现的端口**及后端需要对接的动作。当前没有真实 F02 业务后端端到端验收记录。

## 调用顺序

1. 患者已授权，后端创建 `processing_mode=analyze` 医疗文档和持久解析请求。`store_only` 不进入本链路。
2. **业务后端 Worker 独占领取 F02 请求**，使用双方约定的入站服务令牌调用 Agent：`POST /internal/v1/medical-parse-requests`，请求头 `Authorization: Bearer <Agent 入站令牌>`、`Idempotency-Key: <request_id>`，JSON 为 `{"request_id":"<UUID>","schema_version":"1.0"}`。Agent 返回 `202 {"request_id":"<UUID>","accepted":true}`。后端目前尚无该派发器；本步骤需要后端侧实现或接入。
3. Agent 使用独立的**后端服务令牌**，从既有后端接口 `GET /internal/v1/agent/medical-parse-requests/{request_id}/inputs` 获取冻结单文档 `content_base64`。该接口由后端在每次读取时验证授权、任务状态、文档版本及文件可用性。Agent 不访问业务数据库或 MinIO。
4. Agent 临时解码文件并调用 Medical Agent。仅把有原文片段及明确页码、能映射到后端类型白名单的内容提交给 `POST /internal/v1/agent/medical-parse-requests/{request_id}/candidates`。空结果明确回传 `no_supported_facts` 或 `insufficient_quality`；解析异常发送 `/fail`。患者逐字段确认由后端处理，Agent 不写入确认事实。

## 映射与安全边界

- 当前映射：检查项→`test_item`，检查值→`test_result`，明确/疑似/既往/排除诊断→带原始确定性的 `diagnosis`，有原文的药名/频次/疗程→对应药物字段；单页报告原文建议可映射到 `recommendation`。每条候选带 `source_locator.page` 与 `excerpt`。不确定页码的多页内容不作为候选提交。
- 原模型的 `mentioned` 诊断不符合后端确定性枚举，跳过。自由文本剂量不强转数值剂量；不支持的单位跳过。质量不足或无支持字段时不制造候选。
- F02 本地任务日志只持久化派发元数据、精确候选/失败回调及状态；不持久化原始报告、base64 内容、临时文件、服务令牌。回调超时重试复用原 `callback_id` 和载荷；后端返回 404/409/422 时停止自动重试，避免绕过任务失效和字段校验。
- F02 与 F08 完全独立。F08 只消费已经由后端确认的医学事实，不接收 F02 原始文件或未确认候选。

## 联调验收

先用合成、单页且可读的医疗报告创建 `analyze` 任务，确认：后端仅领取一次、Agent 返回 202、受控输入读取成功、候选回调 204、患者候选列表显示且逐字段决定后产生确认事实。再检查空候选结果、过期/撤权后的 404 或 409、重复派发、回调响应丢失重试和失败回调。多页扫描件的来源定位与真实模型提取效果单独验收。

Agent 侧本地测试：`python -m unittest tests.test_f02_adapter -v`。它使用模拟后端，不替代上述真实环境验收。

运行配置沿用现有 Agent 服务：`GCA_INTERNAL_TOKEN` 是后端派发时使用的 Agent 入站令牌；`GCA_BACKEND_BASE_URL` 与 `GCA_BACKEND_SERVICE_TOKEN` 用于 Agent 回访后端的受控输入和回调接口。`GCA_MODE=mock` 只验证协议和候选格式，不能证明医学文档抽取效果；`GCA_MODE=live` 另需 `GCA_API_KEY` 及可处理报告图片的模型配置。令牌和报告内容不得提交到仓库。

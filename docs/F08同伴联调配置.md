# F08 同伴联调配置（可直接照做）

适用范围：在同伴电脑上启动本仓库 Agent，与已经运行的业务后端验证 F08“派发 → 冻结输入 → 分析 → 回调 → 患者查询”。**首轮使用 mock，不需要模型 API Key，也不会产生真实识图结果。**本说明不代表真实后端任务闭环已经验收。

## 1. 准备信息

只需由后端部署方确认三项值：

| 值 | 用途 |
|---|---|
| 后端 API 根地址 | Agent 能访问，例如同机 `http://127.0.0.1:8000`；两机联调时填后端的局域网/VPN/HTTPS 地址。 |
| Agent 入站令牌 | 后端 Worker 调用 Agent `POST /internal/v1/tasks` 时使用，对应 Agent 的 `GCA_INTERNAL_TOKEN`。 |
| 后端服务令牌 | Agent 读取冻结输入和回调后端时使用，对应 Agent 的 `GCA_BACKEND_SERVICE_TOKEN`；后端需配置匹配的 `AGENT_SERVICE_TOKEN`（或其兼容配置名）。 |

两种令牌可按后端实际配置使用相同值，但两个配置项都必须存在。令牌只通过安全渠道交接，不填入仓库、聊天或截图。业务后端还需配置 Worker 的 Agent 派发目标、专用测试任务和所需数据库；这些不能由 Agent 仓库代替配置。

## 2. 在 Agent 电脑启动

安装 Python 3.12+，在仓库根目录打开 PowerShell，先安装依赖：

```powershell
python -m pip install -r requirements.txt
```

然后把命令中的后端地址换成实际地址并运行：

```powershell
.\run-f08-integration.ps1 -BackendUrl "http://127.0.0.1:8000"
```

脚本会隐藏输入两种服务令牌，自动设置 `GCA_MODE=mock`、后端地址和服务鉴权，再启动 Agent 于 `127.0.0.1:8100`。已有环境变量 `GCA_INTERNAL_TOKEN`、`GCA_BACKEND_SERVICE_TOKEN` 时不会再次询问。脚本退出后会恢复它本次修改过的环境变量，不会把令牌写入文件。若 PowerShell 拒绝运行脚本，可在**当前终端**使用 `Set-ExecutionPolicy -Scope Process Bypass` 后重试。

后端与 Agent 不在同一台电脑时，在 Agent 电脑上改为：

```powershell
.\run-f08-integration.ps1 -BackendUrl "https://<后端可访问地址>" -AgentHost 0.0.0.0 -Port 8100
```

此时后端 Worker 的派发目标必须是 `http://<Agent 电脑可访问地址>:8100/internal/v1/tasks`，不能填写后端电脑自己的 `127.0.0.1`。仅在受控局域网/VPN或受控 HTTPS 代理后开放该内部接口。

## 3. 验证

另开终端，在 Agent 电脑检查 `http://127.0.0.1:8100/healthz`；后端电脑也要能访问 Agent 地址。后端 `/health/ready` 应为 200。然后用隔离测试库准备合成患者、授权、已确认记录和一条 `pending` F08 任务，由**一个** Worker 领取并派发。成功判据是：Agent 收到派发并读取冻结输入、后端收到结果或失败回调、患者身份查询看到对应任务终态。完整步骤见[后端联调交付说明](后端联调交付说明.md)。

脚本的 `-CheckOnly` 只验证本机配置并退出，不会连接后端或处理任务。若需改用真实模型，在拥有模型服务密钥之后加 `-Mode live`；脚本会隐藏输入 `GCA_API_KEY`，默认采用 `.env.example` 中的硅基流动地址及模型名。若使用其他服务，应事先设置 `GCA_BASE_URL`、`GCA_TEXT_MODEL`、`GCA_VISION_MODEL`。live 会消耗模型额度，且图片准确性仍需单独评估。

`.env.example` 仅供查看可用字段；本仓库代码不会自动读取 `.env` 文件。直接使用上述脚本即可完成 F08 所需的 Agent 侧环境变量设置。仓库没有附带真实令牌或模型 API Key。

# 答辩问答手册（智能体部分）

> 用途：决赛答辩与初评追问时的一页一答。每条给出**一句话回答 → 展开 → 代码/文档位置**，
> 确保任何队员都能指到具体实现，而不是背稿。
> 版本 0.2.0 · 2026-10-17。数字均来自 `docs/测试报告.md` 的真实运行结果。
> 本文引用的是历史测试快照；答辩前应按当前代码重测并更新数字与功能状态。

---

## A. 架构与分工

### Q1. 你们这套和"一个大模型分几段 prompt"有什么区别？

**一句话**：分工落在**工具与失败语义**上，不是换个名字重复同一段提示词。

- `Trend` 的主计算在程序里（`stats.py`），模型只负责解释数字；
- `Stool` 的手动记录校验不调用模型；图片质量评估与 Bristol 候选才调用视觉模型；
- `Medical` 有三套输出契约（报告 / 转写 / 医嘱文书），按任务加载不同提示词（`prompts/medical.*.v1.md`）；
- `Conversation` 对药物/诊断类问题**不调模型**，直接给固定安全回应（`agents/conversation.py`）；
- 各 Agent 的失败语义不同：领域识别失败不阻塞、趋势失败会显式传给建议、建议失败仍保留观察。
- 位置：`gutcare_agents/agents/`、`gutcare_agents/stats.py`、`docs/系统设计_智能体章节.md` §2。

### Q2. 为什么计数、分布要放在代码里算？

**一句话**：模型不能改数，数字才可核对、可复现。

- `stats.compute_facts` 负责计数、缺失日、Bristol 分布、服药打卡口径、餐次→症状 6 小时邻近；
- 模型只输出叙述，叙述里的"带单位数字"必须能在事实表中找到，否则该条被删除（`validation.check_numeric_grounding`）；
- 用测试包的 `business_answers.json` 逐条比对：**90/90 完全一致**（`eval/run_eval.py`、`tests/test_core.py`）。

### Q3. Orchestrator 具体做什么？不是多余的中间层吗？

**一句话**：它负责"顺序、依赖、失败、复用"，不负责医学判断。

- 阶段：`intake → domain(并行) → trend → advice → validate`，逐段落库，`GET /v1/tasks/{id}` 可看真实进度；
- 领域 Agent 结果按"文件哈希 + 模型 + 提示词版本 + 子任务"缓存复用（`_domain_cache_key`）；
- 同输入快照幂等复用旧任务；注入故障的任务不进入复用，避免污染；
- 协作式取消只在阶段之间生效，已完成结果保留（`POST /v1/tasks/{id}/cancel`）。

### Q4. 为什么不用 LangGraph / AutoGen / 向量库？

**一句话**：比赛周期内，"评审能读懂、断网能跑、出错能定位"比框架先进更重要。

- 手写 DAG（约 300 行）可以逐行解释阶段、超时、重试与降级；
- 零第三方依赖：评审机 `python -m gutcare_agents serve` 直接跑，不需要 pip；
- 检索用字符二元组 + TF-IDF（`knowledge_base.py`），引用指向知识条目 id，可核验；
- 取舍与代价写在 `docs/系统设计_智能体章节.md` §8，不藏着。

## B. 智能与安全

### Q5. 怎么保证模型不瞎说？

**一句话**：三层确定性校验，不合规内容**直接删**，不是"提醒模型注意"。

1. **结构**：必填字段、状态枚举、`needs_confirmation` 必须给出字段清单；
2. **证据**：每条观察/建议的引用必须能解析回本次输入记录、知识条目或图像区域，解析不了就丢弃；
3. **安全**：禁用表述（加量/停药、确诊、因果、绝对化、精确热量、凭图诊断、延误就医）+ 数值落地检查。
- 位置：`validation.py`；被删条目会留下 `findings`（`action=dropped`），前端能解释"为什么少了一条建议"。

### Q6. 能举一个被"拦住"的例子吗？

**一句话**：例如"高脂饮食导致你的腹胀"会被判为因果断言并删除。

- 校验器识别 `导致/引起/造成/诱发`，但不误杀"不能据此认定因果"这类安全否定句（`_negated`）；
- "建议把药量加倍"命中 `dosage_change`；"这张照片可以确诊为肠炎"命中 `photo_diagnosis`；
- 建议若引用了不存在的 `obs_999`，该条被删除（`validate_advice_items`）；
- 用例：`tests/test_core.py::TestValidation`。

### Q7. 危险征象提示为什么不能交给大模型？

**一句话**：紧急提示不能等模型，也不能由模型决定阈值。

- 独立规则路径 `POST /v1/safety/check`：纯 Python 求值、同步、毫秒级，模型故障照常工作；
- 规则文件 `knowledge/safety_rules.json` 带 `rule_set_version` 与 `review_status`；
- 同事件 1 小时去重；"已读"只改状态，不代表风险解除；
- 模型不可用时的降级路径单独测过（`tests/test_core.py::TestOrchestrator.test_pipeline_runs_and_persists` 等）。

### Q8. 规则和医学知识是谁审核的？

**一句话**：**没有审核**，全部标记 `unverified_demo`，真实上线前必须由专业人员逐条签版。

- 规则文件、6 条知识条目、返回体里的 `review_status` 与免责声明都如实标注；
- 我们不宣称任何临床有效性，`docs/第三方模型与数据使用说明.md` §3 写明；
- 这是刻意的取舍：演示用示例 + 明确标注，好过假装"已审核"。

### Q9. 报告里有"疑似"，模型会不会写成确诊？

**一句话**：不会，诊断状态是四个枚举，`suspected` 不能升级为 `confirmed`。

- 提示词要求输出 `confirmed / suspected / history / mentioned`，并给出原文片段；
- 抽取结果一律是**候选值**：`needs_confirmation=true`，由患者确认后才进入档案（确认归后端）；
- 校验器还会拦截"确诊为/诊断为"这类表述（`diagnosis_claim`）。

### Q10. 图片识别不准怎么办？

**一句话**：允许"识别不了"，不允许编。

- 模糊/非食物图返回 `recognizable=false`，状态 `insufficient_data`，但**仍可文字保存**；
- 禁止输出热量与营养素克数（`energy_estimate` 校验）；
- 排便图像分类流程已实现，只提供待患者确认的 Bristol 形态候选；测试包没有真实标注图像，所以不声称准确率。

## C. 工程与可靠性

### Q11. 模型挂了会怎样？

**一句话**：分阶段降级，记录与安全提示不受影响。

- 领域识别失败 → 该阶段标失败，其余继续，`report.degraded` 说明；
- Trend 失败 → 建议阶段收到 `upstream_trend_failed`，明确写"上游未完成"，不伪装成"数据不足"；
- 建议失败 → 观察与风险提示保留，`advice_status.status=failed` + 原因；
- 可用 `--fault advice` 现场复现（`tests/test_pipeline.py`）。

### Q12. 重复点击"开始分析"会不会产生一堆报告？

**一句话**：不会，同输入快照幂等复用。

- 快照哈希 = 记录 id/version/status 集合 + 档案版本 + 文件列表；
- 同患者 + 同类型 + 同快照 → 直接返回已有任务（`report.reuse.reused_task_id`）；
- `force_refresh` 可强制重跑；异步占位任务（queued）不会被当成可复用结果（`store.find_by_idempotency`）。

### Q13. 超时和重试怎么设计的？会不会写出重复数据？

**一句话**：只对瞬时错误重试，写库按 task_id 覆盖，不会重复。

- 超时：单 Agent ≤60s（`GCA_TIMEOUT_S`），整体建议后端 200s；
- 重试：`model_timeout / model_unavailable / agent_timeout / model_rate_limited`，指数退避、最多 2 次；
- 结构错误只做一次"带校验反馈"的修复重试，再错就降级；
- 落库用 `INSERT ... ON CONFLICT(task_id,agent) DO UPDATE`，天然幂等。

### Q14. 患者甲能不能看到患者乙的数据？

**一句话**：智能体侧对每条记录做归属校验，越权直接 400。

- 请求里的记录只要 `patient_id` 与请求不一致 → `patient_scope_violation`；
- 分析输入只取 `confirmed` 且属于该患者的记录（`TaskRequest.confirmed_records`）；
- 数据库适配层用 `mode=ro` 打开，连写都写不进去；
- 用例：`tests/test_api.py::test_safety_rejects_cross_patient_record`。

### Q15. 为什么用 SQLite，不用 Postgres？

**一句话**：生产状态归后端，智能体侧只需要可打包、可复现的任务记录。

- 单文件、零安装、评审机直接跑；WAL 支持边写边读（并发测试已覆盖）；
- 正式环境由业务后端承担任务权威状态、通知与权限，这一点在边界文档里写明；
- 代价：不适合多实例并发写入——已知，且不在本责任域。

### Q16. 并发会不会锁库？

**一句话**：已开启 WAL + 忙等超时，6 路并行分析实测无锁错。

- `PRAGMA journal_mode=WAL`、连接 `timeout=10s`；
- 测试：`tests/test_concurrency.py`（6 路并行、边写边读、journal_mode 断言）。

### Q17. 改了提示词，怎么知道结果变化是提示词造成的？

**一句话**：结果里带 `prompt_version` 与 `prompt_sha256`，可定位到当时那份文本。

- 提示词在 `prompts/`，改内容必须新增版本文件；
- `tests/test_prompts.py` 校验"Agent 声明的版本文件真实存在且三套医疗提示词互不相同"；
- `replay` 模式可用同一份录制复现旧结果。

### Q18. 换模型要改多少？（已实测）

**一句话**：改三个环境变量，业务代码不动；已用两家真实服务各跑通过一次。

- `GCA_BASE_URL` / `GCA_TEXT_MODEL` / `GCA_VISION_MODEL`；接口走 OpenAI 兼容协议；
- 模型专属逻辑只在 `llm.py`；Agent 只依赖结构化契约；
- **未验证项**：视觉输入格式需用真实账号冒烟确认（当前环境无外网），失败会明确报错并降级。

## D. 评测与合规

### Q19. 90/90 是不是自己出题自己答？

**一句话**：不是，答案是测试包自带的，我们只做输入适配，没有改答案。

- `reference_answers/business_answers.json` 由测试包提供；我们比对 `eligible_record_ids` 与 `record_counts`；
- 一致性来自"筛选口径"（只取 confirmed、按时间窗、按版本）而不是模型能力——这正是我们要证明的；
- 模型相关能力（报告抽取、识菜、OCR）**没有金标准，我们标为未测**，不写数字。

### Q20. 消融实验做了吗？结果是什么？

**一句话**：做了，8 例：单模型的不支持结论率 29.1%、违规表述率 4.2%，多智能体经校验后都是 0%；代价是慢 2.2 倍、token 多 33%。

- `eval/ablation.py`：同一模型、同一批病例、**两边都给相同的事实表与知识**，只改架构；
- 指标：证据完整率、引用失效率、不支持结论率、违规表述率、耗时、token；
- 目前 `eval/ablation.json` 是 `status: skipped` 并写明原因——不造数。

### Q21. 数据合规怎么保证？

**一句话**：只用合成与公开脱敏数据，评测答案不进模型可读范围。

- 测试包来源与许可见 `docs/第三方模型与数据使用说明.md` §2；
- `reference_answers/` 只被评测脚本读取，不进提示词、不进检索索引；
- 不长期保存患者原始图片（只缓存结构化结果，键为文件内容哈希）；
- 日志不打印报告原文与药品信息。

### Q22. AI 工具用了多少？核心代码谁写的？

**一句话**：用了 AI 辅助写草稿与测试，架构、契约、校验与安全边界由队员确定。

- 声明见 `docs/第三方模型与数据使用说明.md` §5；
- 每位队员应能指出自己负责模块的关键取舍（见本手册各条"位置"）；
- 未用 AI 伪造运行结果或测试数据；仓库提交历史为真实开发过程。

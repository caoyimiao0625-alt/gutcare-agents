# 演示脚本（8—10 分钟实机演示 / 录制视频素材）

> 目标：用可复现的操作证明四件事——多智能体真的在分工、结论有证据、异常会降级、数据是隔离的。
> 所有操作都只依赖本仓库 + 测试包，不需要先起 APP（APP 演示可在同一时间轴里穿插）。

## 0. 演示前 3 分钟准备

```powershell
cd gutcare-agents
$env:GCA_FIXTURE_ROOT="<本机测试包目录>"
$env:GCA_MODE="replay"          # 现场优先 replay：断网也不翻车
$env:GCA_INTERNAL_TOKEN="demo"
python tools/demo_run.py        # 预热：把 6 步演示先真跑一遍，确认每步都有结果
python -m gutcare_agents serve  # http://127.0.0.1:8100/
```

- `tools/demo_run.py` 会在 `data/demo/<时间戳>/` 留下每一步的 JSON 与 `transcript.md`，
  现场若某一步意外失败，可以直接展示这份“刚才真跑出来的记录”；
- 浏览器打开 `http://127.0.0.1:8100/`（演示控制台），保持一个终端窗口备用；
- 若现场网络可用，可另开一个 `live` 实例做对照（可选）；
- 提前跑一次分析，确认控制台能出图（避免现场首次冷启动）。

## 1. 开场（30 秒）——先讲边界，再讲亮点

> “我们做的是消化道慢病院外管理。智能体这一侧只做推理，不做诊断、不改药。
> 团队把它拆成 7 个角色：调度、医疗、饮食、排便、趋势、建议、助手，另加一条**不依赖模型**的安全规则路径。
> 下面我用 6 个场景证明它不是‘一个大模型换几个名字’。”

## 2. 场景一：报告抽取，候选值必须人工确认（90 秒）

终端：

```powershell
python -m gutcare_agents run --case MED002 --view summary
```

讲解点：

1. 抽出来的是**候选字段**：`needs_confirmation=true`、`confirmation_fields` 明确列出要确认什么；
2. 每条观察都带 `source_refs: p1`，能回到报告原页；
3. 遮挡处写 `[遮挡]`，原文没有的单位不补造；
4. “疑似/考虑”不会被写成确诊——这是 `suspected` 与 `confirmed` 的区别（可现场再跑一份内镜报告对比）。

## 3. 场景二：识菜只到“看得见的程度”（60 秒）

```powershell
python -m gutcare_agents run --case FOOD001 --view summary
```

讲解点：

1. 只列可见食物，标注置信度与画面依据；
2. 不给热量、不给营养素克数（校验器会拦截 `kcal/千卡` 这类输出）；
3. 模糊图 → `insufficient_data`，但**仍可文字保存**，不阻断记录。

## 4. 场景三：危险征象不等待模型（60 秒）

控制台点“黑色柏油样便”，或终端：

```powershell
python -m gutcare_agents safety --json '{"patient_id":"SYN001","records":[{"record_id":"d1","patient_id":"SYN001","kind":"stool","occurred_at":"2026-10-16T08:00:00+08:00","data":{"bristol_type":6,"note":"黑色柏油样大便"}}]}'
```

讲解点：

1. 这条路径**完全不调用模型**，同步毫秒级返回；
2. 返回里带 `rule_id`、`rule_version`、`review_status: unverified_demo`——规则是示例，需专业审核；
3. 同一事件 1 小时内去重，不会反复轰炸；已读只改状态，不代表风险解除；
4. 现场可以拔网线/停模型再点一次，提示照样出（这就是“两条安全路径”的意义）。

## 5. 场景四：综合分析，四个阶段看得见（180 秒）

控制台选 `SYN001` → 最近 7 天 → “开始分析”。

讲解时按屏幕上的阶段时间线逐条说：

1. `intake`：先跑安全规则、检查数据是否够（不调模型）；
2. `domain.stool`：并行做领域校验，失败不阻塞；
3. `trend`：**数字全部由程序算**（计数、缺失天、Bristol 分布、餐次→症状 6 小时内邻近），模型只负责解释；
4. `advice`：检索知识库 → 生成建议 → 每条带 `obs_xxx` / `KB-xxx` 依据；
5. `validate`：把无依据、违规、数字对不上的条目**删掉**，删除记录在“校验发现”里。

关键话术：

> “这条建议下面挂的两个编号，一个能点回本次的观察，一个能点回知识条目；
> 如果对不上，它就不会出现在这里——不是提示模型注意，是直接删。”

## 6. 场景五：改一条记录，重新分析（90 秒）

```powershell
python -m gutcare_agents analyze --patient SYN001 --days 7 --force --view summary
```

讲解点：

1. 输入快照哈希包含记录 id/version/status，改了记录哈希就变，不会悄悄复用旧结论；
2. 同一张图/同一份报告不会重复解析（`domain.*` 阶段显示“复用已确认的识别结果”）；
3. 历史报告保留生成时的输入版本，旧建议标记“依据已更新”，不被无痕改写。

## 6.5 场景五-b：取消正在运行的分析（30 秒，可选）

控制台点“开始分析”后立刻再点一次“取消”（或终端 `POST /v1/tasks/{id}/cancel`）。

讲解点：

1. 取消是**协作式**的：只在阶段之间生效，不会把半截结果写库；
2. 已完成的阶段结果保留，重新发起时可以复用（不浪费已花的 token）；
3. 已结束的任务不会被“取消”覆盖——避免把已完成的分析误标为取消。

## 7. 场景六：故障注入 + 数据隔离（90 秒）

```powershell
python -m gutcare_agents analyze --patient SYN002 --fault advice
python -m gutcare_agents analyze --patient SYN009 --days 365   # 未确认诊断
```

讲解点：

1. `advice` 阶段失败 → 任务 `partial`，**记录和风险提示都在**，`advice_status` 写明原因；
2. 上游失败用 `upstream_trend_failed` 显式传给下游，不会被伪装成“数据不足”；
3. `SYN009` 没有已确认诊断 → 不给疾病专属建议，只说明缺什么（不编造）；
4. 切到另一个患者：所有记录、任务、建议都以 `patient_id` 为边界，跨患者记录会被直接拒绝（`patient_scope_violation`）。

## 8. 收尾（30 秒）——把“可验证”说透

> “三句话总结：第一，计数和筛选由程序算，模型不能改数，90/90 与测试包答案一致；
> 第二，每条建议都能追溯，追不到就删，违规词与凭空数字都会被拦；
> 第三，模型挂了、图糊了、没确诊、数据不够，每种情况都有明确降级路径，不会假装成功。
> 我们还把真实调用录制成了 replay，评审现场断网也能复现同一份结果。”

## 9. 时间分配与备用方案

| 段落 | 时长 | 备用方案 |
|---|---|---|
| 开场 | 30s | — |
| 报告抽取 | 90s | 网络不通 → 用已审核的 `replay` 录制；仅展示接口结构时，可运行 `python tools/make_samples.py` 生成 mock 样例 |
| 识菜 | 60s | 同上；强调“不给热量”的校验拦截 |
| 危险征象 | 60s | 必做（不依赖网络） |
| 综合分析 | 180s | 控制台卡顿 → 终端 `analyze --view summary` |
| 重新分析 | 90s | 跳过，只讲哈希与复用 |
| 故障+隔离 | 90s | 必做（不依赖网络） |
| 收尾 | 30s | — |

## 10. 评委可能追问的问题（提前准备答案）

| 问题 | 回答要点 |
|---|---|
| 多智能体和“一个 prompt 分段写”有什么区别？ | Trend 的主计算在 `stats.py`（代码）；Stool 手动记录校验不调模型、图片候选调用视觉模型；Medical 有不同输出契约；Conversation 对决策类问题直接不调模型；失败语义各自不同 |
| 怎么保证模型不瞎说？ | 三层校验：结构、证据可解析、安全+数值落地；删条留痕（`findings`） |
| 有没有做对比实验？ | 有，`eval/ablation.py`，同模型/同病例/同事实表/同知识，只改架构；mock 下显式 skipped，不造数 |
| 规则是谁审的？ | 没有审。全部标 `unverified_demo`，真实上线前必须专业审核并签版——我们在 UI 与返回体里都如实标注 |
| 数据合规怎么做？ | 只用测试包合成/公开脱敏数据；`reference_answers` 不进提示词；不长期保存原图；不打印原文到日志 |
| 为什么不用 LangGraph / 向量库？ | 见 `docs/系统设计_智能体章节.md` §8：评审可读、零安装、断网可演示；代价写在表里 |
